# 段階進化型ツム v1 実動試作品

内部ID: `evolutionTsum`。SL6優先、SL1〜6共通ロジック。指定の時間・閾値・81.2の巻き込み半径を維持。

## 起動と試遊

```powershell
node scripts/serve.mjs
```

通常の選択画面から「段階進化型ツム」を選択できる。SL6をすぐ試す場合:

http://127.0.0.1:8765/?tdk=1&tsum=evolutionTsum&sl=6&types=3

`types=4` または `types=5` でも試せる。開発URLは保存データを読み書きしない。「スキル充填」→ Space またはスキルボタン→通常のチェーン操作。開発パネルの「進化ツム計測JSONを保存」で完了済み最大30回と現在のスキルの計測を保存する。再試験ボタンで盤面を再開できる。

この作業環境では確認用サーバーをポート8766でも起動した。8765が既に使われている場合は `$env:PORT='8766'; node scripts/serve.mjs` を使う。

## 実装

- 3倍速のチェーン消去間隔と消滅アニメーション。通常のチェーン入力を維持。
- 最初のライン、PHASE 2、PHASE 3、反復ラインを順序つきキューで処理。超過数と複数回発動を保持。
- PHASE 2では手動チェーン全ノードから固定半径81.2の巻き込み。IDで重複を除外。
- PHASE 3では既存スケール修飾を利用し、全ツムと新規補充ツムの描画・接触・入力半径を1.2倍にする。通常大型ツムの評価方式を維持した上で消去評価を2倍にし、物理消去数と分離。
- 1チェーン全体を既存ClearPipelineの1イベントで評価し、コイン・スコアを一度だけ付与。手動マイツムだけ10%、ODは評価後20%。巻き込み・自動ラインはゲージ0。
- 進化判定には大型ツムの評価重みやOD倍率を含めず、物理ノード数を使用。自動ラインの消去は条件に加えない。
- 手動チェーン確定・消去完了後にイベントを開始。入力中に割り込まない。進化は次のチェーンから適用する。
- 演出中は通常時計・スキル時計・コンボ・フィーバー・実ゲームの経過時計と入力を停止。消去、物理、補充、描画、表示用エフェクトは継続。次の操作と次のラインに必要な盤面量を確認して復帰。
- 補充待ち上限2.5秒、消去イベントの監視上限4秒。初回も反復もライン発射前に対象の補充を確認。ボムでツム数が少なくなった盤面ではツム数に応じた復帰判定を行う。上限後も中央が疎な場合は最密の縦ラインへ照準を移し、予約した攻撃を空振りさせない。監視復帰は既存の確定処理を一度だけ実行し、回復回数を計測に残す。
- OD中の上側境界による押し戻しをこのツムだけ解除。既存の「完全にプレイ領域に入ったツムだけ直接なぞれる」条件を維持し、上端の直接なぞれないツムを巻き込みで狙える。
- 終了時刻をまたぐチェーンと予約イベントを完了してから解除。サイズ修飾と消去速度の元値を復元。再発動・リセット時は古いキューとコールバックをセッションIDで隔離。
- PHASE・残り時間・次の条件の進捗は盤面下に1つの小さな表示。進化時は短いバナー・波紋・合成音、自動ラインは短い光帯。

## 初期調整値

指定外の値は `tsums/evolutionTsum/skill.js` の `EVOLUTION_TUNING` に集約した。必要マイツム24、コイン補正`correction_0`、中央x=207、ライン半幅72、ライン演出0.18秒、進化演出0.48秒、最低補充待ち0.14秒。消滅自体は3倍速で処理する。指定のSL別閾値・効果時間は`evolutionSpec`と定義テーブルで保持。

## 変更ファイル

- `tsums/evolutionTsum/definition.js`, `skill.js`, `image.svg`, `skill.test.mjs`: 新ツム定義・実装・画像・専用テスト。
- `tsums/catalog.js`: 新ツムを通常選択に登録。
- `game.js`: 新ツム限定のイベント更新・時計/入力ロック・終了繰延・ゲージ対象分離・上側境界処理と表示の接続。消去パイプラインには任意の速度倍率を追加。
- `gameplayTiming.test.mjs`: 新ツムの開始演出400msを期待値に追加。既存ツムの期待値は変更しない。
- `tdk/development.js`: 新ツムの計測JSON保存ボタン。
- `scripts/test-evolution-browser.mjs`, `scripts/benchmark-evolution.mjs`: ブラウザ検証と3戦略の自動計測。
- `package.json`: 専用コマンドと全体テストへの追加。4msのp95制限を持つ既存物理テストとCPU負荷の高い実ゲーム試験が競合しないよう、全体テストはファイル単位の直列実行にした。
- `docs/qa/evolution-v1/`: 計測JSON・ブラウザ画面・検証結果。

DOPA・PHOTON LOOM・ナミネの専用ロジック、コイン計算式、物理ソルバー本体は変更していない。新ツム未使用時の既存挙動は全体回帰テストで確認。

## 検証と計測の読み方

`npm test`、`npm run test:evolution`、`npm run tsum:validate` を使用。専用15件はSL全設定、進化順・繰越、巻き込み重複、実消去数、評価2倍、コイン1回、回収率、物理/入力半径、入力保護、時計停止/同時復帰、終了/再発動、監視復帰、本体時間切れ、初回ラインの補充待ち、疎な盤面の照準復帰、通常時の復元を実ゲーム処理で検証する。

初回の全体並列実行では、既存の物理p95試験が4.632msで4ms制限を超えた。物理試験単独17件、全体直列436件は通過。その後、本体時間切れ・補充待ち試験を加えた最終全体テストは438/438件通過。`qa/evolution-v1/validation.txt` に記録した。制限値や物理処理を緩和していない。

ブラウザはローカルChromiumで、実マウス・実タッチ経路、時間切れをまたぐ入力、自然な3種盤面での進化と復元、JSON保存を検証。PHASEごとのPNGを目視し、新規SVGの寸法不足による描画ずれを修正した。PHASE表示も盤面下へ移して上端を空けた。音声の生成コードは実装したが、人が実際に聞いた音量・音質の評価は未実施。

具体的な測定値と比較表は [測定結果](qa/evolution-v1/MEASUREMENTS.md)、元データは `browser.json` と `simulation.json`。

計測項目:

- `phase2AtSec`, `phase3AtSec`: 演出停止を除いたスキル経過時間での解放時刻。未到達はnull。
- `phase3PlayableSec`: OD中、演出/予約イベント/消去による入力ロックを除いたゲーム時間。なぞり中の時間は含む。
- `realClears`, `manualClears`, `splashClears`: 物理消去数。realClearsには自動ラインも含む。倍率評価後のHUD消去数とは異なる。
- `coins`: スキル開始から確定終了までの生コイン増分。終了画面の最終アイテム倍率を適用する前。
- `lines`: 初回+反復の自動縦ライン回数。
- `stoppedSec`, `wallSec`: フレームから渡されたdtを積算した演出停止時間とスキル全体時間。高速シミュレーションでは仮想時間。
- `stoppedWallSec`, `realWallSec`: `performance.now()`で測った実際の停止時間と全体所要時間。ブラウザでの実時間はこちらを見る。高速シミュレーションでは計算に要した実時間なのでプレイ時間と比較しない。
- `gauge`: 消去時に発行されたマイツムゲージ加算量。飛行中のゲージも含み、ゲージ上限による取りこぼしを差し引く前。
- `watchdogRecoveries`, `refillTimeouts`: 安全復帰の発生回数。

## 制限と次の調整

人による面白さ・操作感・音の確認、実機スマートフォンの画面比率・タッチ感は未検証。CPU・最強モードの新ツム専用戦略は未実装（通常の手動プレイが対象）。

ブラウザの自動マウス操作と、固定入力時間のシミュレーションは大きく異なる。前者はツムの移動・実入力のサンプリング・ブラウザとの通信待ちを含み、ODの実操作時間が0になる試行もある。最終段階への到達や強さの保証は追加していない。自動試験だけで「面白い」「人でもこの性能」とは判断しない。

まずユーザーのSL6試遊で、長チェーンの確定率、上端巻き込みの扱いやすさ、ODを操作できた時間、イベント停止の長さを比較する。次に未指定のコスト24・中央ライン幅/位置・演出/補充待ちを調整する。指定された閾値や半径、10%/0%の回収率は今回維持している。

## Git

作業ブランチは `codex/staged-evolution-v1`。`origin/main` をfetchし、その最新コミットを含む既存ローカルHEADから分岐。元ブランチの既存コミットと未追跡のROI資料は保護した。ローカル実装依頼と安全なブランチの指定に従い、mainへの取り込み・リモートpushは行っていない。
